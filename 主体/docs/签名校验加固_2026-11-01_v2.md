# 灵珑聊天 · 签名校验加固记录（V0.0.7，2026-11-01）

## 起因

用户问「签名校验是怎么搞的？感觉很容易出问题」→ 审查后确认：**设计没问题，实现有 4 处真漏洞 + 1 处架构限制**，
全部修掉。

## 原来的设计（三层）

1. **发送**：`canonical(发件人, 收件类型, 收件 id, 时间戳, seq, prev, 正文SHA256)` 用 EC P-256 私钥 ECDSA 签名，
   `sig` 与密文一起交给服务端，服务端原样转发（不参与验签）。
2. **接收**：解密信封后核 ① 信封 `f` == 服务端行的 `from_wxid` ② ECDSA 验签 ③ 消息链 `seq` 接续、`prev` == 上一条签名哈希。
3. **附件**：文件本身 AES-GCM（有 tag），但**附件元数据不在签名内**。

## 修掉的 5 个问题

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | 自己发的消息，`peerPub` 取的是**对方公钥**（`from==我` → `peer=toId`） | **每条自己发的消息重启后都被标「签名校验失败」**（演示：自己签自己验=True，用对方公钥验=False） | 自己发的消息改用**我的公钥**验；验不过只标「未校验」，不告警（换过密钥的旧消息会验不过，属正常） |
| 2 | 附件 `{fid,name,size,kind,mime}` 不在签名范围 | 服务端可把 fid 换成同会话另一个文件，验签照样过 | **签名方案 v2**：`canonicalV2` 把附件（长度前缀编码，无拼串歧义）+ 收件信息一起签 |
| 3 | 收件信息 `tt/ti`（信封里）被忽略，只信服务端那一行 | 服务端把 to_id 改成别人时，靠签名里的 toId 兜住（本来就绑了），但信封与记录不一致没显式检查 | 信封 `tt/ti` 必须与记录一致，不一致直接判篡改 |
| 4 | `verifyAny` 有 4 种宽松格式，其中两种连 `seq/prev` 都不绑 | 老格式签的消息可被改序号/重放而不被发现 | 新消息一律 `sv=2` + **只认 `s2` 严格签名**，缺 `s2` 直接判失败（**不降级**）；宽松格式只用于读 V0.0.6 及以前的历史消息 |
| 5 | 消息链「漏一条毁一条」：中间有消息解不开/没收到 → `lastSeq` 卡住 → **后面所有消息永久误报「断链」** | 换钥/丢消息后满屏告警 | 序号只许前进：`seq > lastSeq` 就接上（缺口只提示这一条），`seq <= lastSeq` 才判重放；缺口不再阻塞后续 |

**兼容做法（关键）**：消息同时带两份签名 —— `sig`（老格式，旧版 App 还能验，升级过渡期不误报）
和信封里的 `s2`（v2 严格签名）。新版**只认 `s2`**，旧版只认 `sig`，两头都不误报、也没有降级通道。

## 没能修掉的（架构限制，写进文档）

- **公钥目录由服务端掌握**：加好友是 TOFU（首次信任），服务端作恶可以换公钥做 MITM。
  缓解手段：换钥时客户端会**弹出提示**「「某某」换了密钥（换机或找回），已自动同步」，加好友时展示安全码可当面核对。
- **多设备同号**：消息链是「一个发件人一条链」，两台设备同时发会让接收方看到缺口（现在只提示不锁死）。

## 证据（可重跑）

**主机端真跑 `Crypto.java`**（把 `android.util.Base64`、`org.json.JSONObject` 换成主机替身，其余是生产代码本身）：

```bash
$JDK/bin/javac -encoding UTF-8 -d out $(find . -name '*.java') && $JDK/bin/java -cp out com.linglum.chat.TestCrypto
```

```
✅ v2 正常验签通过
✅ 【修复1】自己发的消息用「对方公钥」验 → 失败（旧实现就是拿对方公钥，重启后必误报）
✅ v2 改序号 seq / 改 prev / 改收件人 / 改收件类型 / 改正文 → 全部验签失败
✅ v2 带附件的消息验签通过
✅ 【修复2】把附件 fid 偷换成同会话另一个文件 → 验签失败
✅ 【修复2】把附件整段删掉 → 验签失败
✅ 老格式消息（sv=1）仍能验签 → 历史记录不会全变成"被篡改"
✅ （已知限制）宽松格式签的老消息 seq/prev 不在签名内 —— 只影响 V0.0.6 及以前
✅ 但老格式的正文仍然被绑住，改正文照样验签失败
✅ 附件规范串用长度前缀，字段边界不会串（a|bc ≠ ab|c）
通过 14 项，失败 0 项
```

## 改了哪些文件

- `app/src/com/linglum/chat/Crypto.java`：新增 `SIG_V2` / `canonicalV2` / `attachSig` / `verifyMessage` / `fld`
- `app/src/com/linglum/chat/MainActivity.java`：
  - 发送：双签名（`sig` 老格式 + 信封 `s2` v2），`env.sv=2`
  - 接收：`decryptTry` 自己消息用自己公钥验；`tt/ti` 一致性检查；`sv>=2` 只认 `s2`；链缺口不再锁死
  - 群成员公钥同步 `syncMemberPubs`（群消息验签不再因「不是好友」而放弃）
  - 换钥时给用户可见提示
- `app/src/com/linglum/chat/ChatService.java`：后台通知同样走 `verifyMessage` + `s2`
