# 灵珑聊天 · 热更新说明（V0.2.0 起）

## 结构

```
安装包（壳，很少变）          补丁（经常变，几十 KB）
├─ MainActivity（薄壳）   →   └─ ChatApp（全部界面/业务逻辑，可整体替换）
├─ HotLoader（加载+验签+回滚）
├─ ChatService / QrScan / 两个 Provider（清单里写死的组件，只能在包里）
└─ Api / Crypto / 数据模型
```

- 启动时 `HotLoader.load()` 先找 `filesDir/patch/classes.dex`：
  验签通过 → 用 `DexClassLoader` 加载补丁里的 `ChatApp`；
  没有/验签失败/连续两次启动失败 → 回落到包里自带的 `ChatApp`。
- 跨 ClassLoader 只能通过 **接口**（`AppCore`）和 **public 类**交互，补丁里的
  `ChatApp` 与壳里的 `ChatApp` 是两个不同的类（不同 Loader），**不能强转成 ChatApp**。

## 发一个热更新（改完代码）

```bash
cd android/chat-app
# 1) 改代码；把 ChatApp.java 里的 BUILD_TAG 改成新版本号（设置页能看到）
# 2) （首次或改了很多东西时）确认能编译
sh tools/quickjavac.sh
# 3) 打补丁（只编 ChatApp；d8 → 签名 → out/patch/）
sh build_patch.sh 2 "这次改了什么" 7      # 参数：补丁号、说明、minShell
# 4) 发布到服务端（data/patch/）
sh publish_patch.sh out/patch
```

用户在 App 里就会收到「热更新已就绪（vN）」→ 立即重启 → 生效。

## 什么时候必须重新装整包

- 改 **图标 / 主题资源 / 权限 / 清单组件**（补丁只有代码，没有资源）
- 改 `ChatService` / `QrScan` / Provider / `HotLoader` 本身（它们在壳里）
- 改 `minShell` 要求更高的新 API 时，老壳装不上补丁（会自动提示整包更新）

## 签名与回滚

- 私钥：`android/chat-app/keys/private.pem`（600，另存 NAS `/vol1/1000/项目/安卓/chat/patch_key/`）
- 公钥：烧在 `HotLoader.PUBKEY_B64` 里；**换密钥 = 必须发新壳**
- 补丁必须验签通过才落盘（`HotLoader.installPatch` 里二次校验）
- 回滚：设置 → 热更新 → 回滚到内置版本（删补丁，重启生效）
- 自动回滚：连续两次启动失败 / 验签失败 → 自动删补丁
- 补丁 dex 落盘后 `setReadOnly()`（Android 14 要求可动态加载的 dex 只读）
