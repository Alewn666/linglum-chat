# 版本检查与强制更新（v1.4）

## 机制

```
App 启动/登录/轮询
      ↓ 带请求头 X-App-Version: <versionCode>
NAS 服务端 /api/version  →  返回 {versionCode, versionName, minVersionCode, url, md5, notes}
      ↓
版本 < versionCode  → 弹「必须更新」对话框（不可取消）
      ↓ 下载 APK（带进度）→ MD5 校验 → 调起系统安装器
版本 < minVersionCode → 服务端对**所有接口**返回 426（除 /api/version、/apk/、/api/health）
```

**双保险**：
- 客户端弹窗是「提示」，不可取消（只能选「立即更新」或「退出」）
- 服务端闸门是「强制」——就算有人改客户端代码绕过弹窗，请求也会被 426 拒绝

## 发布新版本（操作步骤）

1. 改 `AndroidManifest.xml` 的 `versionCode`（+1）和 `versionName`
2. 打包：`cd 主体/app && sh build_apk.sh` → `out/linglum-chat.apk`
3. 把新 APK 放到 `主体/server/data/apk/`（容器内是 `/data/apk/`）
4. 更新 `主体/server/data/apk/version.json`：

```json
{
  "versionCode": 6,
  "versionName": "1.5",
  "minVersionCode": 6,
  "file": "linglum-chat-1.5.apk",
  "md5": "<md5sum 新 APK>",
  "notes": "本次更新内容"
}
```

- `minVersionCode` 决定「最低能用版本」：
  - 设为最新 → 所有人强制更新
  - 设为旧值 → 只提示，不强制
- 改完无需重启服务端（每次请求都读文件）

## 当前状态

- 服务端版本：**1.4（code 5）**，`minVersionCode = 5`
- 也就是说：**1.3 及更早的客户端现在会被服务端拒绝（426）**，必须装 1.4

## 实测（2026-10-31）

```
GET /api/version                    → versionCode 5, minVersionCode 5, url/md5 齐全
GET /api/messages（无版本头）        → 426  ✅ 旧客户端被拒
GET /api/messages（X-App-Version:5）→ 401  ✅ 新客户端放行（未登录才 401）
GET /apk/linglum-chat-1.4.apk      → 200，41630 字节，md5 与 version.json 一致 ✅
```

## 注意

- 下载的 APK 会做 **MD5 校验**，对不上直接丢弃并提示「文件校验失败」
- Android 8+ 需要在系统里允许「安装未知应用」（App 会引导跳转设置）
- 安装包走自定义 `ApkProvider` 以 `content://` 交给安装器（Android 7+ 不允许 file://）
