# 灵珑聊天 · 检查与修复记录

## 2026-11-01 · 找回账号后聊天无法解密 → 公钥自动同步（V0.0.6）

### 结论

**根因不是「找回」本身，是公钥不同步。**

审计日志（`server/data/audit.jsonl`）里那次找回是：

```
{"wxid": "ceshi", "action": "recovery_finish", "result": "ok", "new_keypair": true}
```

`new_keypair: true` = 本机没有旧私钥 → 客户端**生成了一对新密钥对**，服务端 `users.pubkey` 换成了新公钥。
但好友手机里缓存的还是**旧公钥**（`prefs.friends[].pubkey`），于是：

- 好友 → 我：好友用「我的旧公钥」算共享密钥 → 我用新私钥算出来的不一样 → 解不开；
- 我 → 好友：我用新私钥算 → 好友用「我的旧公钥」验算 → 一样对不上 → 好友也解不开。

双向全断，所以表现成「找回账号后聊天全部无法解密」。

### 修复（照微信：只要是加上的好友就一直能聊）

不再要求「重新加好友」，改成**公钥由服务端下发、客户端自动对齐**：

| 位置 | 改动 |
|---|---|
| 服务端 `users.pubkey_ver` | 换密钥对时 +1（`recovery_finish`）；登录接口也返回 `pubkey_ver` |
| 服务端 `GET /api/pubkeys?ids=a,b,c` | 批量取**当前**公钥 + 版本号（需登录；非法 id 过滤、去重、最多 50 个） |
| 客户端发送前 | `refreshPeerPub(toId)`：先问服务端要最新公钥再加密（网络失败退回缓存，不阻塞发送） |
| 客户端解密失败 | `pollOnce` 里改为**强制刷新**对方公钥后重解一次（原来是读本地缓存，等于没刷） |
| 客户端全局 | 登录时 + 每 2 分钟 `refreshAllFriendKeys()` 对齐所有好友公钥 |
| 客户端历史 | `Friend.oldPubs` 保留最近 3 个历史公钥：**对方换钥前的旧消息仍能解密** |
| 后台服务 `ChatService` | 每 60 秒对齐好友公钥；新消息解不开时单独拉一次对方公钥重试 |
| 群聊 | `group_keys` 加 `wrapped_by`；任何人换钥后，**手上还有群密钥的群成员会自动 rewrap** 给他（`POST /api/groups/<gid>/rewrap`）；客户端每 2 分钟 `refreshGroups()` 取新包裹 |
| 顺带修 | `recover_codes` 表从未在 `init_db()` 里创建（新装库走找回直接 500）；注册限流 5/h → 20/h |

**历史消息**：本机没有旧私钥时，换钥前的旧消息**在数学上无法恢复**（ECDH 私钥丢了就是丢了，微信换机也一样）。
现在的表现是明确提示「🔒 无法解密（换密钥前的旧消息，新消息正常）」，而不是静默空白。


`test_keyrotation_e2e.py` 的关键断言：

```
✅ ③ 旧公钥对不上：alice 解不开 bob 发的（复现 bug）
✅ ④ 用新公钥后：alice↔bob 共享密钥重新一致
✅ ⑤ alice 换钥后，旧包裹解不出群密钥（群聊断）
✅ ⑤ bob 替 alice 重新包裹群密钥 → alice 解得回群密钥 → 群聊恢复
```

### 还没做 / 已知限制

1. **旧消息无法恢复**：换钥前用旧私钥加密的内容解不开（数学上限，微信换机也一样），
   界面上明确显示「🔒 无法解密（换密钥前的旧消息，新消息正常）」。
2. 群聊恢复需要**至少还有一个成员持有群密钥**并在 2 分钟内打开过 App（自动 rewrap）。
   如果全群只有换钥那个人用过这个群，群密钥无法重建 —— 需要重新拉群。
3. 两端都要升到 V0.0.6：旧版 App 仍会用缓存的旧公钥，照样解不开新消息。
