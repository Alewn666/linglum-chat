# 灵珑聊天 · 签名校验修复（V0.0.7，2026-11-01）

## 结论

上一轮（V0.0.6）只修了「公钥不同步」。本轮把**签名校验**里两个真会出问题的地方修掉了，
外加把「宽松验签」和「消息链漏一条毁一条」也收紧：

| # | 问题 | 修法 |
|---|---|---|
| 1 | 🔴 **自己发的消息重启后会被标「签名校验失败」**：`from==我` 时 `peerPub` 取的是**对方**公钥，签名却是自己私钥签的（最小复现：用自己公钥验=True、用对方公钥验=False） | 自己发的消息改用**自己的公钥**验；若验不过（换过密钥前的老消息）→ 记 `verified=0` 不告警 |
| 2 | 🔴 **附件的 `fid` 不在签名范围内**，服务端可把消息指向同会话另一个文件 | 新增 v2 规范串，把附件按**固定字段顺序 + 长度前缀**（`attachSig`）纳入签名；信封带 `sv:2` 标明方案 |
| 3 | 🟠 宽松验签 4 种格式（后两种连 `seq/prev` 都不绑） | `sv>=2` 只认 v2 严格格式、缺 `s2` 直接判失败**不降级**；只有无 `sv` 的历史消息才走旧兼容 |
| 4 | 🟠 消息链漏一条 → 后续全部永久误报「链不连续」 | 缺口只提示那一条，`lastSeq` 照常前进；`seq<=lastSeq` 仍判重放 |
| 5 | 🟠 群消息发件人不是好友时完全不验签 | 群内遇到不认识的发件人 → 先向 `/api/pubkeys` 取一次公钥再验 |
| 附 | 信封里的 `tt/ti`（收件信息）之前没核 | 现在必须与服务端那一行一致，否则判篡改 |

**兼容性**：过渡期双签名 —— 信封里同时带老的 `sig`（服务端列）和新的 `s2`。
V0.0.6 ↔ V0.0.7 互发都不报错；V0.0.7 收到 `sv=2` 只认 `s2`。

- `Crypto.java` 新增 `SIG_V2 / fld / attachSig / canonicalV2 / verifyMessage`
- `MainActivity.java:1541` 发送时双签；`:1807-1852` 按 `sv` 选严格/兼容 + 自己消息用自己公钥 + 核 `tt/ti`
- `MainActivity.java` 群消息分支：陌生发件人先 `refreshPeerPub` 再验
- `ChatService.java:314-325` 通知路径同步改（缺 `s2` 判篡改，不降级）
- 链：`seq<=lastSeq` 判重放；`seq != lastSeq+1 || prev 不匹配` → 只提示该条并继续

## 还没做 / 仍是已知限制

1. **公钥目录由服务端掌握**（TOFU + 可选当面核对指纹）→ 服务端作恶可做 MITM。这是架构假设，不是 bug；
   若要根治需做 key transparency / 交叉签名。
2. **旧消息**（换密钥前的）仍无法解密，界面已明确提示。
3. 群聊里若**全群只有换钥那个人**持有过群密钥，群密钥无法重建（需要重新拉群）。
4. V0.0.6 及更早版本仍用宽松验签（旧格式），需两端都升到 V0.0.7 才真正收紧。
