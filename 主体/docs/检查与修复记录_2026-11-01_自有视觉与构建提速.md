## ② 平板点左栏 → 聊天区横向跳动

根因：左侧页签点击走的是 `showTab()` → `reset()` → 整棵视图树重建，
重建瞬间右侧（weight=1）会先按旧宽度量一次再纠正 → 看起来"跳一下"。

修法：**只换左栏，不动右边**
- 新增 `wideLeftHost` / `railItemViews` 记录平板左栏容器和页签文字
- 点页签 → `currentTab = idx; refreshWideTabs();`：清空左栏容器重新填内容 + 改页签颜色，
  **聊天区完全不重建**，自然不会跳
- 左栏宽度从「屏宽 32%」改成固定 `300dp`，避免不同设备/旋转后宽度突变

## ③ 构建提速

原来每次 5~8 分钟，主要开销是两个 qemu 模拟的 x86 工具（aapt2 / zipalign）和 600KB 的 zxing 每次重新 dex。

| 优化 | 做法 | 效果 |
|---|---|---|
| 资源编译缓存 | 对 `res/` + `AndroidManifest.xml` 算 md5，命中就跳过 aapt2 compile/link，复用 `base_res.apk` | 省掉最慢的 qemu 环节 |
| 依赖预编译 | `libs/*.jar` 只 dex 一次，产物缓存 `libs/.dex_*.dex`，之后作为 `classes2.dex` 直接打进包 | 不再每次 dex 600KB |
| 只 dex 自己代码 | d8 只处理 `build_tmp/classes` | 140KB vs 680KB |

**实测**：本次全量构建（第一次带缓存初始化）`1:49`，CPU 229%；下次改 Java 重打预计 ~1 分钟。
APK 仍是 `classes.dex`（自研）+ `classes2.dex`（zxing），minSdk 21 原生支持多 dex。
